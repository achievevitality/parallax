## Why this belongs on Page One, not just in the archive

This is Brenda naming, in one breath, that the company's actual product is
congruence — communication and service delivery operating at the same
dimensionality as the underlying method, not a simplified public-facing
version bolted onto a separate internal reality. Her own framing: clients
feel the difference before they've signed anything, because the
transformation is already happening in how they're met. If staff write
emails or handle scheduling in a flattened, generic-service-business way
while the actual work operates at full dimensionality, the dissonance is
structural, not cosmetic — "nails on a chalkboard," in her words.

## Translation task for the actual handbook (not done yet)

Each clause needs a plain-language, actionable version a new hire could
apply without first learning kernel vocabulary:
- Reality-coupled → grounded in what's actually true for this client, not a template
- Consequence-sensitive → aware of what this message actually costs/changes for the person receiving it
- Corrigible → easy to correct without defensiveness if we got it wrong
- Capable of relinquishing itself when no longer needed → doesn't create unnecessary ongoing dependency

This is a real translation project, not a copy-paste — flagged for the
